# @partssource/react-kit

The PartsSource Design System, packaged as a React + TypeScript component library. **22 component families** sourced 1-for-1 from the Figma design system and the `preview/*.html` reference pages.

> **Using this in a product app?** Read **[CONSUMING.md](./CONSUMING.md)** — it's
> the sanctioned, only-supported way to install and stay on-system. To enforce
> the no-rogue-color rule inside your app too, add
> **[@partssource/eslint-config](./eslint-config/README.md)**.

## Install

```bash
npm install @partssource/react-kit
```

`react` and `react-dom` are peer dependencies — bring your own (>=18).

## Tokens — required at app root

The components reference CSS custom properties (`--ps-prim-*`). Import the token
stylesheets **once** at your app's entry point, or the components render without
their brand colors:

```ts
import '@partssource/react-kit/tokens.css';
import '@partssource/react-kit/colors.css';
```

## Tailwind setup

Components use Tailwind arbitrary values (`bg-[#005BA6]`, `shadow-[0_0_10px_5px_rgba(0,91,166,0.5)]`, etc.). Your app's `tailwind.config.js` must scan this package's source so JIT picks them up:

```js
// tailwind.config.js (consumer app)
module.exports = {
  content: [
    './src/**/*.{ts,tsx}',
    './node_modules/@partssource/react-kit/dist/**/*.js',
  ],
  // …
};
```

The kit's own `tailwind.config.js` is also exported if you want to extend it:

```js
const kitConfig = require('@partssource/react-kit/tailwind.config');
```

## Usage

```tsx
import {
  Button,
  Input,
  Modal,
  Alert,
  EventCard,
  StatusBadge,
  FolderTabs,
} from '@partssource/react-kit';

export function App() {
  return (
    <div>
      <Button variant="primary">Buy Now</Button>
      <Input label="Email" />
      <StatusBadge tone="success">Delivered</StatusBadge>
    </div>
  );
}
```

## Development

### Storybook

```bash
npm run storybook        # http://localhost:6006 — dev server with HMR
npm run build-storybook  # static export to storybook-static/
```

Stories live next to each component file: `src/Button.stories.tsx`, `src/Card.stories.tsx`, etc. The `.storybook/` config wires up the `@storybook/addon-a11y` (axe) and `@storybook/addon-essentials` packages.

**This is the primary tool for component review and visual regression** — the live `UI Kit/index.html` Showcase remains for quick previews in this design tool, but Storybook is the canonical workshop for engineers.

## Local development

```bash
npm install
npm run dev       # Vite dev server (open the showcase)
npm run build     # build dist/ (ESM + CJS + .d.ts)
npm run typecheck # tsc --noEmit
npm run build:css # compile Tailwind to tailwind.css (offline use)
```

### File layout

```
UI Kit/
├── src/                 ← Component source — EDIT HERE (proper ES modules)
│   ├── Button.tsx
│   ├── Input.tsx
│   ├── ...
│   └── index.ts         ← Barrel export
├── scripts/
│   └── sync-to-browser.mjs  ← Generates root .tsx from src/
├── *.tsx                ← AUTO-GENERATED browser copies (do NOT edit)
├── tokens.ts            ← Brand color + type tokens
├── tailwind.config.js   ← Theme extension
├── tailwind-input.css   ← Tailwind entry
├── index.html           ← Live showcase (in-browser Babel for dev preview)
├── Showcase.tsx         ← Showcase component (browser-only)
└── dist/                ← Build output (generated)
```

### Single source of truth

`src/*.tsx` is canonical. The root `UI Kit/*.tsx` files are generated by
`scripts/sync-to-browser.mjs` and carry an "AUTO-GENERATED" banner — they
exist solely so the in-browser Babel showcase can load components without
a build step. **Never hand-edit the root files**; edit `src/` and run:

```bash
npm run sync:browser   # regenerate root *.tsx from src/
```

`npm run dev` and `npm run build` run the sync automatically.

## Design provenance

Every component is sourced from either:
- A Figma frame in the design library (`Design System & Component library`)
- The HTML reference in `../preview/*.html`

When a component drifts from Figma we treat the `.fig` as canonical and document the diff in a code comment. See [`../TOKEN_AUDIT.md`](../TOKEN_AUDIT.md) for the running audit log.
